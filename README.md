# Дневник молодого ученого

**Версия 1.0.0 · первый этап · Windows x64 · C# / WPF / .NET 8 · SQLite**

Локальная программа для ведения научных проектов: паспорт и страницы проекта, задачи и календарь, исследовательский дневник, библиотека источников, таблицы измерений, базовая статистика, отчёты и полные резервные копии.

Программа работает с собственной папкой данных на вашем компьютере. Учётная запись не нужна. Интернет требуется при первой загрузке зависимостей для сборки и при явном запросе метаданных публикации по DOI. Основная работа выполняется локально.

Исходный код программы и встроенные оригинальные шаблоны распространяются по **Apache License 2.0**. Сторонние компоненты имеют собственные лицензии; они включены в комплект.

## 1. Быстрый запуск из исходников

1. Распакуйте архив целиком, например в `C:\Projects\YoungScientistDiary`. Не запускайте сборку внутри ZIP.
2. Установите **.NET 8 SDK для Windows x64** с [официальной страницы Microsoft](https://dotnet.microsoft.com/en-us/download/dotnet/8.0). Для сборки нужен SDK, одного Runtime недостаточно.
3. Откройте папку с `YoungScientistDiary.sln` и запустите **build.bat**.
4. Дождитесь загрузки пакетов, сборки и завершения проверок. При успешной сборке программа сообщит путь к результату.
5. Запустите **dist\YoungScientistDiary\YoungScientistDiary.exe**.

`build.bat` останавливается при ошибке. Он восстанавливает зафиксированные зависимости, собирает решение в Release, запускает автоматические проверки и публикует приложение. Visual Studio для этого способа не требуется.

Обычная публикация требует **.NET Desktop Runtime 8 x64** на компьютере, где запускается приложение. На компьютере с установленным Windows .NET 8 SDK он уже есть. Переносите всю папку приложения, включая DLL и документы.

Для другого компьютера без установленного .NET выполните **publish-standalone.bat**. Он создаёт `dist\YoungScientistDiary-standalone` со встроенной средой выполнения. Эта папка заметно больше; её также нужно переносить целиком. Сначала рекомендуется выполнить обычный `build.bat` с проверками.

Подробности командной строки, Visual Studio и устранения ошибок: [docs/BUILD.md](docs/BUILD.md).

## 2. Первое знакомство

На странице **«Сегодня»** нажмите **«Учебный проект»**. Программа создаст один пример с паспортом, задачами, страницей, дневниковой записью, протоколом, календарным событием, карточкой источника, шестью парами чисел и сохранённым парным расчётом. Повторное нажатие откроет тот же проект.

**Все данные и источник в учебном проекте вымышлены.** Они нужны только для освоения программы. Пример не создаётся автоматически и не подменяет ваши проекты.

Для своей работы:

1. Откройте **«Проекты → Создать проект»**, заполните название, цель, гипотезу и сроки.
2. В проекте перейдите в **«План»**, создайте задачи и назначьте время через **«Запланировать время»**.
3. В **«Страницах»** запишите методику и замысел; в **«Дневнике»** фиксируйте фактический ход работы.
4. Добавьте источники в **«Литературу»**, привяжите их к проекту.
5. Создайте или импортируйте таблицу в **«Данные и статистика»**.
6. Выполните расчёт, сохраните комментарий и подготовьте отчёт.
7. В **«Настройки и копии»** выберите место для архивов и создайте первую копию.

| Раздел | Что в нём находится |
| --- | --- |

| Литература | Карточки источников, коллекции и теги, статусы чтения, файлы, DOI, импорт, дубликаты и оформление библиографии. |

В верхней панели выберите конкретный проект или **«Все проекты»**. Фильтр применяется к рабочим спискам; каталог проектов остаётся доступен целиком. Источник может входить сразу в несколько проектов.

Поле поиска в верхней панели ищет по сохранённым названиям и текстам записей. Введите запрос и нажмите **Enter**. Двойной щелчок открывает найденный объект. Поиск не выполняет OCR и не индексирует содержимое прикреплённых PDF.

## 4. Проекты, страницы и задачи

### Паспорт проекта

Предусмотрены название и короткое обозначение, тип работы, состояние, сроки, цель, гипотеза, проблема, актуальность, объект и предмет, новизна, методы, ожидаемые результаты и критерии их достижения, организация, руководитель, участники, оборудование, ресурсы, риски, финансирование, теги и цвет.

У проекта есть внутренние вкладки **«Обзор»**, **«План»**, **«Страницы»**, **«Дневник»**, **«Источники и данные»**. Последняя открытая вкладка запоминается. Завершённый проект можно перевести в архив, сохранив материалы.

### Собственные страницы

У нового проекта создаются три начальные страницы. Дополнительные страницы можно создавать и переименовывать, задавать порядок и родительскую страницу. В списке отображается путь родительского раздела.

Редактор поддерживает обычный текст, размеры заголовков, полужирное и курсивное начертание, подчёркивание, списки, вставку таблицы 3 × 3, изображений и отдельные вложения. Страницы экспортируются в RTF. Область форматированного документа остаётся белой при обеих темах, чтобы текст и экспорт имели предсказуемый цвет.

**Текст страницы сохраняется примерно раз в три секунды**, при переходе и штатном закрытии. Можно сохранить немедленно кнопкой или **Ctrl+S**. Кнопка **«История»** показывает предыдущие сохранения и позволяет восстановить одно из них. Восстановление само создаёт новую запись истории.

Если сохранение завершилось ошибкой, исправьте причину и нажмите **«Сохранить»**: успешное ручное сохранение возобновит таймер. Не закрывайте процесс принудительно при несохранённых изменениях.

### План работы

У задачи есть состояние, приоритет, этап, родительская задача, срок, описание, отметка контрольной точки, плановые и фактические часы, результат. Действие **«Выполнено»** фиксирует дату завершения.

**Срок задачи и время работы над ней — разные значения.** Для одной задачи можно назначить несколько календарных сеансов. Перенос сеанса не меняет срок задачи. Фактические часы заполняются вручную; автоматического таймера работы в этой версии нет.

## 5. Календарь

В режимах **«День»** и **«Неделя»** показаны 24 часа с вертикальной прокруткой. События пересечения размещаются рядом. Двойной щелчок по свободному месту создаёт событие, по событию — открывает свойства.

Событие можно перетащить на другое время с шагом 15 минут. Перенос меняет один экземпляр и сохраняет его длительность. Длительность редактируется в свойствах через начало и конец.

Доступны события на весь день и конечные серии: ежедневно, еженедельно, по рабочим дням, ежемесячно, до 180 экземпляров. Для существующей серии можно изменить один экземпляр либо всю серию. При редактировании программа предупреждает о пересечении с другими событиями. В месяце показаны также сроки задач; кнопка **«Ещё…»** открывает оставшиеся события и сроки дня.

Удаление одного события или всей серии доступно в режиме **«Список»**. Записи перемещаются в корзину.

Напоминание задаётся в минутах до события; **−1** отключает его. Напоминания появляются **пока программа работает**, в том числе когда окно свёрнуто. При полностью закрытом приложении уведомлений нет. Часы событий используют локальное время Windows; синхронизации часовых поясов и внешних календарей в версии 1.0 нет.

## 6. Исследовательский дневник

Типы записей: рабочая запись, эксперимент, наблюдение, встреча с руководителем, разбор статьи, идея/гипотеза и промежуточный вывод.

В карточке можно сохранить цель, условия, материалы, ход работы, отклонения, наблюдения, результат, характер результата, вывод, следующий шаг и теги. Поддерживаются связь с проектом и задачей, вложения и история изменений. Отрицательные и неопределённые результаты можно отмечать явно.

**«Следующая задача»** создаёт задачу из следующего шага записи. **«Протоколы»** открывает библиотеку методик: редактирование методики создаёт новую версию, а проведённая работа сохраняет ссылку на использованную версию и её текст в поле хода работы.

Карточки сохраняются кнопкой **«Сохранить»** или **Ctrl+Enter**. Незавершённый ввод в открытой карточке не является сохранённой записью.

## 7. Литература и библиография

### Сбор и разбор источников

Можно вручную создавать и редактировать карточки статей, книг, глав, диссертаций, конференционных материалов, интернет-ресурсов, отчётов и патентов. Есть поля авторов, выходных данных, DOI, ISBN, URL, аннотации, заметок, цитат с указанием страниц, исследовательского вопроса, методов, выводов, ограничений и полезности для проекта.

Авторы в форме вводятся через точку с запятой, например: `Иванов, Иван; Петрова, Анна`. Организация как автор указывается в фигурных скобках, например `{Институт биологии}`.

Доступны коллекции, теги, состояния чтения, поиск, сортировка, связь с несколькими проектами и поиск возможных дубликатов. Объединение дубликатов выполняется после просмотра: заполненные конфликтующие поля остаются из основной карточки, пустые дополняются, заметки, связи и вложения объединяются.

Поддержан импорт и экспорт **RIS, BibTeX, CSL JSON**. Импорт сначала показывает найденные карточки и предупреждения. Если у публикации есть DOI, можно запросить её метаданные из Crossref и проверить карточку перед сохранением. Эта операция не скачивает полный текст статьи.

**PDF и другие вложения копируются в папку данных**, затем открываются установленной программой Windows. При открытии файлу устанавливается признак «только чтение», чтобы редактор не изменил сохранённый оригинал. Для правок используйте «Сохранить копию…», затем добавьте отредактированный файл как новое вложение. Встроенного PDF-редактора, распознавания текста и автоматического анализа содержания статьи пока нет.

### Оформление списка

Выделите источники и нажмите **«Сформировать библиографию»**. Если выделения нет, используются видимые строки. Выберите встроенный шаблон либо загрузите совместимый независимый файл **.csl**. Список можно предварительно просмотреть, скопировать или экспортировать в **TXT, RTF, DOCX, HTML**.

В комплекте три оригинальных базовых шаблона: русский числовой, автор–год, английский числовой. **Они не обозначены как официальные реализации ГОСТ, APA или Vancouver.**

Реализован документированный **профиль CSL для библиографии**, а не весь стандарт. Неподдерживаемые значимые правила вызывают объяснение несовместимости. Раздел внутритекстовых ссылок не применяется. PDF или DOCX с правилами журнала можно приложить как материал; такие документы автоматически в правила оформления не преобразуются.

Сохранённый список фиксирует текст, порядок источников, стиль и его контрольную сумму; исходный CSL и RTF входят в резервную копию. Последующая правка карточек не переписывает этот снимок.

Подробности поддерживаемого CSL и особенностей библиографического обмена: [docs/CSL-SUPPORT.md](docs/CSL-SUPPORT.md).

## 8. Данные, статистика и графики

### Таблицы и версии

Создайте таблицу вручную, вставьте строки из Excel или импортируйте **CSV/TSV/TXT/XLSX**. В мастере импорта выбираются разделитель, кодировка, строка заголовка и лист XLSX; перед сохранением есть предварительный просмотр. Старый формат XLS в этот этап не включён.

Для столбца задаются имя, тип, единица измерения, роль и описание. Исходный файл копируется во вложения. Десятичная точка и запятая поддерживаются; для CSV с десятичной запятой удобен разделитель `;`.

Правки таблицы сохраняются **новой версией** по кнопке **«Сохранить версию»**, по **Ctrl+S**, при переходе, перед анализом/экспортом и при штатном закрытии. У таблицы нет трёхсекундного таймера: при длительном вводе используйте Ctrl+S.

Предыдущие версии доступны в истории. Исходные значения не перезаписываются. Сортировка заголовком переставляет строки целиком; она текстовая, поскольку редактируемые ячейки хранятся как введённые строки.

### Реализованные методы

| Метод | Основные результаты |
| --- | --- |
| Описательная статистика | Число наблюдений, среднее, медиана, минимум/максимум, квартили, выборочное стандартное отклонение, стандартная ошибка и доверительный интервал среднего. |
| t-тест Уэлча | Сравнение независимых групп, разность средних, t, степени свободы, p-value, доверительный интервал, размер эффекта. |
| Парный t-тест | Сравнение полных пар из одной строки, разность, t, p-value, интервал и размер эффекта. |
| Корреляция Пирсона | r, p-value и, когда применимо, интервал по преобразованию Фишера. |
| Корреляция Спирмена | Корреляция рангов; до 9 пар — полный перестановочный расчёт p-value, далее — явно обозначенное приближение. |
| Простая линейная регрессия | Модель Y от одного X: коэффициенты, R², ошибки и интервалы коэффициентов, прогнозы и остатки. |

Можно выбрать доверительный уровень, альтернативную гипотезу, группы и исключаемые строки. Программа показывает использованные и исключённые строки с причинами, сообщает о некорректных числах и вырожденных случаях. Для парных методов используются пары из одной строки; отдельное удаление пропусков из двух столбцов не выполняется.

Каждый расчёт сохраняет **версию данных, параметры, числовой результат, сведения об исключениях, версию вычислительного модуля и ваш комментарий**. Изменение таблицы не обновляет старый расчёт автоматически.

Предусмотрены гистограмма, последовательность значений, диаграмма рассеяния, ящик с усами, средние с интервалами, Q–Q, линия регрессии, остатки и Q–Q остатков, где они применимы. Графики экспортируются в **PNG и SVG**, таблицы — в **CSV и XLSX**, результаты — в текстовые/документные форматы и JSON.

Программа рассчитывает показатели выбранным методом; проверка дизайна исследования и статистических предпосылок остаётся частью интерпретации. Точные формулы, обработка пропусков, направление разностей, ограничения методов и форматы результатов описаны в [docs/STATISTICS.md](docs/STATISTICS.md).

Примеры для импорта: `samples/experiment.csv` и `samples/regression.csv`. Они также содержат искусственные учебные данные.

## 9. Отчёты

Выберите проект либо все проекты, задайте период и нажмите **«Сформировать»**. В отчёт входят паспорт, завершённые задачи, дневниковые записи, сохранённые анализы с версиями данных, текущие открытые задачи, календарный план и связанные источники.

Плановые интервалы не выдаются за фактически выполненную работу. Источники включаются как подборка проекта; оформление полноценной библиографии выполняется в разделе литературы.

Текст можно дописать перед экспортом в **DOCX, RTF или TXT**. **Черновик правок в окне отчёта сохраняется только при экспорте** и не изменяет исходные записи.

## 10. Где находятся данные

По умолчанию:

`%LOCALAPPDATA%\YoungScientistDiary`

Главная база — **diary.db**. Рядом хранятся собственные копии вложений, стили и прочие управляемые материалы. Отдельный SQL Server устанавливать не требуется: используется встроенная SQLite.

В **«Настройки и копии → Открыть папку данных»** можно увидеть актуальный путь. После перехода к другому хранилищу оно запоминается для последующего запуска. Одно хранилище нельзя одновременно открыть двумя экземплярами программы.

Чтобы создать отдельное пустое рабочее пространство, можно запускать:

    YoungScientistDiary.exe --workspace "D:\ResearchDiary"

Экспортированный на рабочий стол отчёт или график не входит в архив программы автоматически. Если документ должен входить в копию, добавьте его во вложения.

Файлы базы и архивы **не шифруются**. Для конфиденциальных данных используйте подходящие права доступа и защиту диска. Не размещайте открытую рабочую базу в папке одновременной облачной синхронизации; передавать можно закрытые проверенные ZIP-архивы.

## 11. Резервное копирование и восстановление

В **«Настройки и копии»**:

1. Выберите папку архивов, при необходимости на другом диске.
2. Оставьте или измените автоматическое копирование и число сохраняемых архивов — по умолчанию 14.
3. Нажмите **«Сохранить настройки»**, затем **«Создать копию сейчас»**.
4. Дождитесь сообщения, что архив создан и проверен. Последняя успешная копия отображается в нижней части окна.
5. Кнопкой **«Проверить архив»** можно повторно проверить выбранный ZIP.

Автокопия выполняется не чаще одного раза в день при изменениях, пока программа запущена. Проверка необходимости идёт при запуске и каждые 30 минут. Во время другой операции или открытой карточки она откладывается. Не требуется держать открытым раздел настроек.

Полная копия содержит согласованный снимок SQLite, историю и корзину, вложения, сохранённые стили и остальные управляемые материалы. Для файлов записываются и проверяются SHA-256; проверяется также целостность SQLite и наличие зарегистрированных вложений. Старые собственные архивы удаляются только после создания и проверки нового.

**«Восстановить архив»** проверяет ZIP и восстанавливает его **в другую пустую папку**. Текущая рабочая папка не перезаписывается. После успеха можно открыть восстановленное хранилище. В нём автоматическое резервирование выключается, а путь архивов назначается заново; выберите нужную папку и явно включите автоматику.

Не копируйте один открытый `diary.db` как полноценную резервную копию: SQLite может использовать WAL, а документы хранятся отдельно. Пользуйтесь встроенной командой.

Полная инструкция и ограничения: [docs/BACKUP.md](docs/BACKUP.md).

## 12. Оформление и удобство

В настройках доступны **«Светлая»**, **«Тёмная»**, **«Системная»** темы. Выбор применяется сразу. Системная тема определяется при запуске и её выборе. Документные листы и экспортируемые графики используют светлый фон.

Основные сочетания:

| Клавиши | Действие |
| --- | --- |
| Ctrl+F | Перейти в общий поиск. |
| Enter в поиске | Выполнить поиск. |
| Ctrl+S на странице или в таблице | Сохранить текущие изменения. |
| Ctrl+Enter в форме карточки | Проверить поля и сохранить карточку. |
| Esc в форме карточки | Закрыть форму без сохранения. |
| Двойной щелчок в списке | Открыть выбранную запись. |

Удалённые записи доступны в корзине настроек. В версии 1.0 корзина не очищается окончательно через интерфейс. История хранится без автоматической обрезки; база может расти при длительной работе с большими материалами.

## 13. Границы текущего этапа

В этой версии ещё нет:

- совместной сетевой работы, учётных записей и синхронизации между компьютерами;
- встроенной разметки PDF, OCR и генерации научных выводов с помощью ИИ;
- полной реализации CSL, гарантированного оформления любого ГОСТ/журнала и обновляемых ссылок внутри Word;
- ANOVA, непараметрических сравнений групп, многофакторных моделей, расчёта мощности и подключения R/Python;
- экспорта/синхронизации внешних календарей, диаграммы Ганта и фоновых уведомлений после закрытия;
- шифрования рабочей базы и ZIP, установщика MSI и цифровой подписи исполняемого файла.

Список реализованного выше описывает фактическую версию. Направления следующих двух этапов и точки расширения приведены в [docs/ROADMAP.md](docs/ROADMAP.md) и [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 14. Проверки и сообщения об ошибках

Комплект содержит автоматические проверки настоящей SQLite, резервирования/восстановления, библиографических форматов и экспорта документов, импорта CSV/XLSX, статистических эталонов и полного учебного сценария. Запуск: **test.bat**.

В среде подготовки выполнены Release-сборка WPF для Windows и проверки вычислительного ядра. **Графический интерфейс не запускался в настоящей Windows в этой среде.** Это первая реализация, поэтому перед переносом основных материалов пройдите учебный сценарий и проверку восстановления. Конкретный список ручной проверки: [docs/TESTING.md](docs/TESTING.md).

При ошибке программа показывает сообщение и записывает технические подробности в **error.log**. Он открывается из настроек. Для сообщения об ошибке достаточно описания действия, версии программы и соответствующего фрагмента журнала; весь ваш научный архив передавать не требуется.
