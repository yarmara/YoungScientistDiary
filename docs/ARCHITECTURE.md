# Архитектура и расширение

## Границы модулей

Решение состоит из трёх проектов:

| Проект / каталог | Ответственность |
| --- | --- |
| Core/Models.cs | Сериализуемые сущности и их стабильные идентификаторы. |
| Core/Storage | SQLite, транзакции, версии записей, вложения, полный архив и восстановление. |
| Core/Literature | Библиографический обмен, Crossref, профиль CSL, экспорт документов. |
| Core/Analysis | Импорт/экспорт таблиц, параметры расчётов, статистика и результаты. |
| Core/DemoData.cs | Явно создаваемый учебный проект с вымышленными данными. |
| App/Views | Экраны проектов, календаря, дневника, литературы, данных, отчётов и настроек. |
| App/PlotWindow.cs | Отрисовка графиков и экспорт PNG/SVG. |
| SelfTests | Воспроизводимые проверки ядра и сценария сохранения/восстановления. |

Core не зависит от WPF. Интерфейс написан на C# и XAML; большинство экранов создаётся в отдельных partial-файлах MainWindow. Это модульное разделение UI и предметной логики, **не полная реализация MVVM** и не готовая система динамических плагинов. По мере роста интерфейса его можно переносить на ViewModel по одному разделу, сохраняя Core и данные.

## Связи данных

- ResearchProject объединяет задачи, страницы, события, записи, наборы данных и расчёты.
- ProjectPage.ParentId и ResearchTask.ParentId задают вложенность внутри проекта.
- CalendarEvent.TaskId связывает сеанс работы с задачей; SeriesId объединяет конечную серию.
- JournalEntry хранит ссылку на задачу и конкретную версию Protocol.
- LiteratureReference.ProjectIds связывает один источник с несколькими проектами.
- Attachment связывается с владельцем через OwnerType/OwnerId; файл копируется под управляемое относительное имя.
- Dataset хранит паспорт таблицы и ссылку на запись дневника.
- DatasetVersion содержит неизменяемый снимок столбцов и строк.
- AnalysisRun ссылается на DatasetVersion и хранит параметры и полный результат.
- SavedBibliography фиксирует список, порядок источников и идентичность стиля.

Ссылки используют локальные идентификаторы; удаления выполняются мягко. В этой версии нет автоматического каскадного удаления проекта со всеми материалами. Архивирование проекта сохраняет весь контекст.

## SQLite: схема 1

Используются таблицы **Entities**, **Revisions**, **Settings**.

Entities содержит тип, ID, проект, заголовок, поисковый текст, даты, признак удаления и JSON типизированной сущности. По основным полям созданы индексы. Revisions хранит снимки редакций. Settings хранит настройки рабочего пространства.

Таким образом, это настоящая локальная SQL-база SQLite с индексируемой оболочкой и JSON-полями предметной модели. В первой версии нет отдельной SQL-таблицы для каждого типа и внешних SQL-ключей на все связи. Ссылочная проверка выполняется сервисами/формами; импорт и будущие API должны сохранять эти инварианты.

Изменение и запись истории выполняются транзакционно. Пакет SaveMany применяется целиком или откатывается. SQL-параметры используются для значений пользовательского ввода. Кириллица нормализуется в поисковом поле; поиск не зависит от ASCII-only NOCASE. Полнотекстового индексатора вложений нет.

DatasetVersion запрещено менять после сохранения; номер версии уникален для набора. Работа редактора идёт на копии, а сохранение создаёт следующий номер. AnalysisRun хранит тот ID версии, который реально использовал вычислительный модуль.

## Согласованность интерфейса

Для редактора страницы и таблицы зарегистрировано отдельное действие сохранения. FlushEditor сохраняет черновик, оставляя редактор активным; LeaveEditor сохраняет и освобождает его таймер/обработчики при переходе.

Закрытие окна отменяется при ошибке сохранения либо пока выполняется блокирующая операция. Во время вычисления, импорта или архивирования отключаются переходы между разделами. Автоматическая копия откладывается при активной операции и открытом модальном окне.

Это защита штатного завершения. Она не превращает несохранённый ввод карточки, черновик отчёта или аварийное завершение процесса в транзакционное автосохранение.

## Вложения и резервные копии

Вложения имеют относительный путь, размер и SHA-256. Программа хранит свою копию исходного файла. Физическое окончательное удаление вложений и очистка истории пока не реализованы.

Полный архив собирается из согласованного SQLite BackupDatabase-снимка и управляемых каталогов. Он включает manifest с хешами и проверяется до подтверждения успеха. Восстановление идёт через промежуточную папку в отдельный пустой каталог; текущая база не перезаписывается.

Подробности — [BACKUP.md](BACKUP.md).

## Миграции

В версии 1 поддерживается только схема 1 и создание нового пустого хранилища. Неизвестная непустая схема 0, чужой application_id, более новая схема и неполная структура отклоняются. Автоматическое исправление чужой или повреждённой БД не выполняется.

При первом реальном изменении SQL-схемы необходимо добавить отдельный MigrationService:

1. Открыть существующую схему в допустимом режиме чтения.
2. Создать и проверить полную копию в формате старой схемы.
3. Выполнить версионированную миграцию в транзакции.
4. Проверить структуру, ссылки и данные.
5. При неуспехе оставить исходное хранилище доступным для восстановления.

Обычное добавление необязательного JSON-поля может не требовать SQL-миграции, но требует совместимых значений по умолчанию и теста чтения старых документов. Не меняйте смысл существующих числовых enum-значений и формата ResultJson без версии формата.

## Как добавить возможности следующих этапов

| Задача | Точка изменения | Что сохранить |
| --- | --- | --- |
| Новый статистический метод | StatisticalMethod, AnalysisRequest, StatisticsService, DataView | Неизменяемую входную версию, исключённые строки, параметры, версию метода и числовые эталоны. |
| Полный CSL-движок | Заменить/расширить CitationService, оставив модели карточек и снимков | Лицензии, явную диагностику несовместимости, исходный стиль и результат. |
| PDF-аннотации | Новый тип сущности и PDF-модуль, связанный с Attachment | Оригинальный PDF, координаты/страницы аннотаций и резервирование дополнительных файлов. |
| Новые шаблоны проектов/протоколов | Сервис шаблонов и экраны выбора | Возможность работы со старыми проектами без зависимости от изменившегося шаблона. |
| Word-интеграция | Отдельный проект надстройки и адаптер к библиографии | Стабильные локальные ID, согласованный формат ссылок, тесты обновления документа. |
| Синхронизация | Отдельный журнал операций, транспорт и разрешение конфликтов | Не копировать открытую SQLite через общий каталог; версии, tombstones, вложения по хешу и явные конфликты. |
| R/Python | Отдельный адаптер вычисления | Изолированный обмен файлами/JSON, контроль версии среды и полный provenance результата. |

Текущая сборка не содержит заглушек, выдающих будущие функции за готовые: эти расширения требуют отдельной реализации.

Прямые пакеты: Microsoft.Data.Sqlite 8.0.21, MathNet.Numerics 5.0.0, ClosedXML 0.104.2. Прямые и транзитивные версии фиксируются packages.lock.json; полный перечень — THIRD-PARTY-NOTICES.md и licenses/dependency-inventory.json.

При изменении зависимостей обновляйте lock-файлы, оригинальные лицензии и числовые/импортные проверки. В автономной публикации отдельно учитываются runtime-pack лицензии. Скрипты из исходников не загружают плагины или произвольный удалённый код во время обычной работы.
