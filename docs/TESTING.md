# Проверка версии 1.0.0

## Что проверено автоматически

Исходники подготовлены в Linux со **SDK .NET 8.0.426**. Сборка WPF выполняется для Windows x64 через Windows targeting pack. Вычислительное ядро запускается непосредственно в .NET 8.

Проверки используют временные папки и настоящую SQLite. Пользовательскую рабочую папку они не открывают. Python, R, Microsoft Office и подключение к Crossref для автоматических проверок не требуются.

| Группа | Основные проверяемые риски |
| --- | --- |
| StorageTests | Транзакционный откат, чтение/запись кириллицы, параметризованный поиск, история и восстановление, корзина, независимые копии вложений, неизменяемость версий, уникальность номера версии. |
| StorageTests: архивы | Полный архив, SHA-256, проверка SQLite, отсутствие вложенной рекурсии архивов, восстановление в отдельную папку, повреждённый ZIP, обход путей, сохранность текущей базы при ошибке, раздельная очистка архивов двух хранилищ в общей папке. |
| StorageTests: схема | Отказ от будущей схемы, неизвестной непустой схемы 0 и отсутствующих обязательных таблиц. |
| AnalysisTests | CSV с кавычками и переводами строк, кодировки, десятичная запятая, чтение/обратный экспорт XLSX и CSV, пропуски и пары, идентификаторы, некорректные числа, крайние случаи, независимость от ru-RU/en-US/de-DE. |
| AnalysisTests: числа | Сравнение с независимыми эталонами для описательной статистики, Уэлча, парного t-теста, Пирсона и OLS; точный Спирмен по числу перестановок; исходная версия не изменяется вычислением. |
| LiteratureTests | RIS/BibTeX/CSL JSON, авторы и организации, ошибочные метаданные/UTF-8, встроенные стили, поддерживаемые CSL-конструкции, явный отказ от несовместимых правил, оформление и документные экспорты. |
| WorkflowTests | Учебный проект → протокол/запись → версия данных → расчёт → новая версия → снимок библиографии → вложение → полный архив → восстановление всех связей и результата. |

Запуск в Windows:

    test.bat

Или из корня исходников:

    dotnet run --project tests/YoungScientistDiary.SelfTests -c Release

SelfTests — консольный выполняемый проект. Поэтому запускайте `dotnet run` или test.bat; вызов `dotnet test` не заменяет эти проверки.

Ожидаемый итог:

    PASS: SQLite, revisions, managed files, backup and restore
    PASS: CSV/XLSX and verified statistics
    PASS: Bibliography imports, CSL formatting and document exports
    PASS: Project-to-analysis-to-bibliography backup and recovery workflow

При ошибке возвращается код 1 и печатается стек исключения. Это четыре группы проверок с множественными утверждениями, а не только четыре отдельных случая.

## Проверка сборки и публикации

Проверены:

- восстановление решения с `--locked-mode`;
- полная Release-сборка, включая WPF;
- выполнение SelfTests;
- framework-dependent публикация для win-x64;
- self-contained публикация для win-x64 со средой .NET 8.0.32;
- копирование лицензий фактически опубликованных runtime-пакетов и проверка их SHA-256;
- отказ helper при намеренно несовпадающей версии runtime;
- повторный locked-mode restore после автономной публикации.

App.csproj сам задаёт win-x64. В standalone-команде намеренно нет глобального `-r`: он передавал бы RID библиотеке Core и менял её lock-файл. Helper сравнивает опубликованный deps.json с точно разрешёнными runtime-пакетами и не подставляет случайную последнюю версию.

Краткий протокол окончательной сборки находится в [BUILD-VERIFICATION.txt](BUILD-VERIFICATION.txt).

## Что здесь не проверено

**Настоящее окно WPF не запускалось на Windows в среде подготовки.** Компиляция проверяет C#/XAML и связывание проектов, но не подтверждает фактическую отрисовку, клавиатурный фокус, взаимодействие мышью, системные диалоги и работу конкретного просмотрщика PDF.

Также не заявлены нагрузочные испытания на сотнях тысяч строк, многогигабайтных библиотеках и разных дисках, испытания Windows UI Automation, проверка всех возможных CSL-стилей, сетевой доступности Crossref и всех форматов файлов внешних программ.

## Короткий контрольный сценарий Windows

Выполните его на отдельном учебном хранилище, например:

    YoungScientistDiary.exe --workspace "%TEMP%\YSD-ManualCheck"

1. **Первый запуск.** Окно открывается, разделы доступны, пустая база создаётся. «Учебный проект» создаёт один пример; повторное нажатие не дублирует его.
2. **Темы.** Переключите светлую/тёмную темы. Проверьте выпадающие списки, выбранные вкладки, таблицы и длинную форму. Закройте и откройте приложение — тема сохраняется.
3. **Карточки и даты.** Измените цель и срок проекта. Введите дату с клавиатуры и сохраните Ctrl+Enter без предварительного выхода из поля. Повторное открытие должно показать новую дату. Неверная дата должна требовать исправления.
4. **Страница.** Введите кириллицу, список, заголовок и изображение. Сохраните, перейдите в другой раздел и вернитесь. Создайте архив из другой вкладки, затем продолжите редактирование страницы — сохранение должно работать и после копии. Проверьте экспорт RTF и восстановление предыдущего текста через историю.
5. **План и календарь.** Свяжите событие с задачей. Перетащите его в недельной сетке, измените длительность в форме, создайте серию и измените один экземпляр. Проверьте, что срок задачи не меняется. Поставьте ближайшее напоминание при открытом приложении.
6. **Дневник.** Создайте протокол, запись с этим протоколом, затем новую версию методики. Старая запись должна сохранять прежний вариант. Из следующего шага создайте задачу.
7. **Литература.** Создайте карточку, экспортируйте и снова импортируйте её, просмотрите и объедините дубликаты. Сформируйте список встроенным стилем, экспортируйте DOCX/RTF и откройте в имеющейся программе. Загрузите собственный CSL: применимый должен работать, несовместимый — объяснять причину.
8. **Таблица.** Импортируйте samples/experiment.csv с разделителем «;». Измените активную ячейку и сразу перейдите в другой раздел; при возвращении правка должна находиться в новой версии. Исходная версия должна сохраниться. Проверьте вставку диапазона, пропуск в паре и повторный идентификатор.
9. **Статистика.** Импортируйте samples/regression.csv, выполните регрессию Y на X. Сверьте контрольные числа из STATISTICS.md. Откройте графики, сохраните PNG/SVG, добавьте комментарий и вернитесь к сохранённому расчёту.
10. **Копия и восстановление.** Создайте ZIP, выполните «Проверить архив», восстановите в другую пустую папку. Откройте её: записи, обе версии таблицы, расчёт, вложения и стиль должны быть доступны. Исходная папка остаётся целой; в восстановленной автоматика копий выключена до вашей настройки.

Если какой-либо пункт не проходит, сохраните описание шагов и соответствующее сообщение из error.log. Прежде чем работать с основными данными, устраните найденную проблему и повторите затронутый сценарий.
