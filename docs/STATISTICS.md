# Данные, расчёты и графики

Этот документ описывает реализованный модуль первой версии «Дневника молодого ученого». Формулы находятся в `src/YoungScientistDiary.Core/Analysis/StatisticsService.cs`, импорт — в `DataImportService.cs`. Расчёты выполняются локально. Для распределений Стьюдента и нормального распределения используется Math.NET Numerics 5.0.0, для XLSX — ClosedXML 0.104.2.

## 1. Работа с таблицей

Откройте **«Данные и статистика»** и создайте таблицу вручную либо импортируйте файл. Для каждого набора можно указать проект, описание и связанную запись дневника. Исходный импортированный файл копируется во вложения рабочей папки. Кнопка **«Исходный файл»** открывает сохранённую копию.

В редакторе доступны изменение ячеек, добавление и удаление строк, вставка диапазона из Excel, словарь переменных, история версий, экспорт и анализ. Кнопка **«Вставить диапазон»** добавляет строки в конец таблицы: количество и порядок столбцов должны совпадать. Перед вставкой можно указать, содержит ли буфер строку заголовков.

**«Столбцы и единицы»** позволяет изменять название, тип, единицу, роль и описание переменной, добавлять и удалять столбцы. Роли включают идентификатор, группу, время, независимый и технический повтор. Тип и роль служат описанием: они не превращают текст в число, не задают статистическую модель и не объединяют повторы автоматически. Анализ проверяет значения выбранных столбцов отдельно.

### Неизменяемые версии

Редактор создаёт рабочую копию строк и описаний переменных. Изменения сохраняются **новой версией** по кнопке **«Сохранить версию»**, по `Ctrl+S`, перед анализом/экспортом, при переходе в другой раздел и при штатном закрытии программы. Постоянного таймера автосохранения таблицы нет: во время продолжительного ввода используйте `Ctrl+S`.

Старая версия не перезаписывается. Если открыть её в истории и внести правки, будет создана новая версия с новым номером и пометкой, на какой версии она основана. Анализ всегда ссылается на конкретный ID версии. После изменения данных старый результат сохраняется; в нём появляется сообщение о наличии более новой версии. Чтобы пересчитать результат, откройте новую версию и запустите анализ снова.

Щелчок по заголовку сортирует **строки целиком**, сохраняя соответствие столбцов. В текущем редакторе ячейки хранятся как строки, поэтому такая сортировка текстовая: например, `10` может находиться перед `2`. При сохранении сортировка становится порядком строк новой версии. Перетаскивание заголовка меняет только расположение столбцов на экране, не их содержание.

## 2. Импорт и экспорт

| Формат | Реализованное поведение |
| --- | --- |
| CSV / TSV / TXT | Разделитель выбирается явно или определяется по первой выбранной логической записи: точка с запятой, табуляция, запятая, вертикальная черта. Для расширения `.tsv` по умолчанию используется табуляция. |
| Кодировки текста | В интерфейсе доступны UTF-8, Windows-1251 и UTF-16. BOM распознаётся автоматически. Ошибка декодирования требует выбрать правильную кодировку. |
| CSV-кавычки | Поддерживаются поля в двойных кавычках, разделители и переводы строк внутри поля, экранированная кавычка `""`, окончания строк LF и CRLF. Незакрытые/некорректные кавычки вызывают ошибку. |
| Заголовки | Можно указать начальную строку и наличие заголовка. Пустые имена заменяются на «Столбец N», повторяющиеся получают суффикс. Недостающие значения в коротких строках дополняются пустыми ячейками. |
| XLSX | Выбор одного листа, начальной строки и наличия заголовка. Читается прямоугольник от столбца A до последнего занятого столбца. Числа считываются как значения; даты — в формате ISO. Старый `.xls` не поддерживается. |
| Формулы XLSX | Импортируются сохранённые результаты формул; формулы не пересчитываются. Перед импортом пересчитайте и сохраните книгу в Excel. Ошибки Excel в ячейках останавливают импорт. |
| Экспорт CSV | UTF-8 с BOM, разделитель `;`, CRLF, корректное экранирование кавычек и переводов строк. Записываются исходные текстовые значения ячеек. |
| Экспорт XLSX | Один лист «Данные», закреплённая строка заголовков. **Все ячейки записываются как текст** для сохранения идентификаторов, ведущих нулей и буквального содержимого. Для вычислений непосредственно в Excel потребуется преобразовать выбранные числовые столбцы. |

В CSV номер начальной строки означает **логическую запись**: поле с переводом строки внутри кавычек остаётся одной записью. В XLSX это обычный номер строки листа.

При импорте показаны первые 30 строк для проверки перед сохранением. Исходное написание текстовых значений сохраняется: `001` не становится `1`, а `1,25` не переписывается в `1.25`. Для числовых ячеек XLSX исходное оформление Excel, например формат отображения `000`, не является содержимым ячейки; если ведущие нули значимы, храните идентификатор в Excel как текст.

Лимиты интерфейса: до **250 000 строк**, до **1 024 столбцов** при импорте, исходный файл до **256 МиБ**, значение ячейки до миллиона символов. Это верхние ограничения, а не обещание одинаковой скорости на любом компьютере. Таблица и её версии загружаются в память; для больших массивов разумно работать с меньшими отдельными наборами. Импорт файла и статистический расчёт выполняются в фоновой задаче. Создание редактора, сохранение большой версии и экспорт в этой версии ещё могут занимать время в интерфейсе.

### Числа и пропуски

При анализе допускаются десятичная запятая или точка, знак, научная запись вида `1.2e-3`. Результат чтения не зависит от региональных настроек Windows. Разделители тысяч не поддерживаются: `1,234` означает **1,234**, а не 1234; `1,234.5` и `1 234,5` отклоняются. В CSV с разделителем-запятой десятичную запятую нужно заключать в кавычки либо использовать разделитель `;`.

Пустая ячейка, строка из пробелов, `NA`, `N/A` и `NULL` означают пропуск; регистр этих обозначений не важен. Пропуски **не заменяются нулями**. `NaN`, `Infinity`, бесконечность после переполнения и произвольный текст в выбранном числовом столбце являются ошибкой. Сообщение указывает строку, столбец и значение. Строку можно исправить или явно исключить в параметрах анализа.

## 3. Параметры анализа и происхождение наблюдений

Нажмите **«Анализ…»**. Укажите название результата, метод, столбец X, при необходимости Y, доверительную вероятность (например, `0,95`) и альтернативную гипотезу. Поля групп используются только для теста Уэлча. Для анализа полных пар можно дополнительно выбрать столбец идентификаторов.

Номера в поле **«Явно исключённые строки»** начинаются с **1** и относятся к текущей сохранённой таблице **без заголовка**. Допускается, например, `2, 7-9`. Номера относятся к выбранной версии, а не обязательно к физическим строкам исходного CSV/XLSX. Сортировка или удаление строк в новой версии меняет нумерацию этой новой версии. Для связи с объектами исследования храните отдельный столбец ID.

Правила отбора:

- **Описательная статистика:** пропуски исключаются в выбранном X.
- **Уэлч по двум столбцам:** X и Y очищаются независимо. Пропуск X в строке не удаляет числовое Y той же строки. Это две независимые выборки; строки не задают пары.
- **Уэлч по группам:** X содержит измеряемый показатель, отдельный столбец содержит группы. Значения первой и второй группы сравниваются точно, с учётом регистра, после удаления пробелов по краям. Остальные группы отмечаются как не вошедшие в расчёт.
- **Парный тест, корреляции, регрессия:** X и Y из одной строки образуют пару. Если одного значения нет, исключается вся пара. Некорректный непустой числовой текст не маскируется пропуском во второй ячейке.
- **Проверка ID:** если столбец выбран для парного анализа, идентификаторы использованных полных пар должны быть заполнены и уникальны. Программа проверяет строки, но не выполняет соединение двух таблиц по ID. Повторные измерения должны быть подготовлены в соответствующем виде заранее.
- **Явные исключения:** применяются до чтения числовых ячеек и фиксируются отдельно; сами данные версии не удаляются.

Результат содержит использованные строки X и Y, пропуски по каждому набору, объединённый список пропусков/исключений и их причины. Для независимых групп объединённое количество исключённых строк не равно сумме пропусков по столбцам: одна строка может присутствовать в обоих списках. В текстовом отчёте длинные списки сокращаются, в JSON сохраняются полностью.

## 4. Реализованные методы

### Описательная статистика

Количество наблюдений, среднее, медиана, минимум, максимум, первый и третий квартиль, **выборочное** стандартное отклонение с делителем `n − 1`, стандартная ошибка среднего и двусторонний доверительный интервал среднего по распределению Стьюдента. При одном наблюдении SD, стандартная ошибка и доверительный интервал не определены и выводятся как таковые.

Квартили используют линейную интерполяцию **Hyndman–Fan type 7**: для отсортированного массива с нумерацией от нуля `h = (n − 1) × p`, результат интерполируется между элементами `floor(h)` и `ceil(h)`. Определения типов квантилей приведены в [документации R](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/quantile.html).

### t-тест Уэлча для независимых групп

Не менее двух числовых наблюдений в каждой группе. Выводятся описательные показатели обеих групп, разность средних **X − Y**, стандартная ошибка разности, t, степени свободы по Уэлчу–Саттертуэйту, p-value, доверительный интервал разности и Cohen d с объединённым выборочным SD. Объединённое SD применяется только к этому варианту стандартизованного размера эффекта; сам тест оценивает дисперсии групп раздельно.

Нулевая гипотеза — разность средних равна нулю. Альтернативы: двусторонняя, меньше нуля, больше нуля. Для одностороннего теста интервал разности тоже односторонний: неограниченная сторона обозначается `−∞` или `+∞` в тексте и `null` в числовом поле JSON. Если обе группы постоянны, стандартная ошибка равна нулю и расчёт теста отклоняется. Одна постоянная группа допускается с пояснением.

Предпосылки связаны с независимостью наблюдений и применимостью t-приближения; малые выборки чувствительны к выбросам и сильной ненормальности. Технические повторы не становятся независимыми только потому, что записаны отдельными строками. Методика и смысл альтернатив сопоставимы с [R `t.test`, `var.equal = FALSE`](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/t.test.html).

### Парный t-тест

Не менее двух полных пар. Для каждой строки рассчитывается **X − Y**; тест выполняется для среднего этих разностей. Выводятся число пар, средние X/Y, средняя разность, SD разностей, стандартная ошибка, t, `df = n − 1`, p-value, интервал разности и Cohen dz = средняя разность / SD разностей. Предпосылка нормальности относится к распределению разностей. Если все разности одинаковы, стандартная ошибка равна нулю и тест отклоняется. Направление односторонней альтернативы и интервала такое же, как для Уэлча.

### Корреляция Пирсона

Коэффициент r вычисляется по полным парам. Для коэффициента нужны минимум две пары и непостоянные X/Y. При двух парах параметрический p-value не вычисляется. При `n ≥ 3` проверка нулевой корреляции использует t-статистику с `n − 2` степенями свободы; при `n ≥ 4` выводится приближённый **двусторонний** интервал Фишера. Выбор односторонней альтернативы влияет на p-value, но не на этот интервал.

Для параметрического вывода предполагаются независимые пары и подходящая двумерная нормальная модель. При идеальной корреляции ±1 p-value вычисляется предельным значением; числовая бесконечность t в JSON не записывается. Условия t-проверки и преобразования Фишера описаны в [R `cor.test`](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/cor.test.html).

### Корреляция Спирмена

Коэффициент ρ — корреляция Пирсона между рангами. Совпадающим значениям присваивается средний ранг. Постоянный столбец не допускается.

**При 2–9 полных парах** p-value вычисляется полным перебором всех `n!` перестановок рангов Y. Совпадающие ранги не исключаются: учитываются все перестановки помеченных наблюдений с соответствующей кратностью. Для двусторонней альтернативы считаются перестановки с `|ρ_perm| ≥ |ρ_observed|`, для односторонней — соответствующий хвост. Число перестановок сохраняется. Нужна обменяемость наблюдений при нулевой гипотезе; этот тест не предназначен для произвольных зависимых повторных измерений.

**При более чем 9 парах** используется t-аппроксимация с `n − 2` степенями свободы. В отчёте она прямо обозначается как приближённая. При небольшом объёме или множестве совпадающих рангов для окончательного вывода может потребоваться специализированный перестановочный метод. Доверительный интервал ρ в этой версии не реализован. Точный алгоритм приложения — собственный полный перебор, он не является реализацией AS 89 из R.

### Простая линейная регрессия

Модель `Y = b₀ + b₁ × X`, обычный метод наименьших квадратов со свободным членом. Требуются минимум три полные пары и непостоянный X. Выводятся коэффициенты, их стандартные ошибки, R², стандартная ошибка остатков, число степеней свободы `n − 2`, t и p-value для нулевого наклона, **двусторонние** интервалы обоих коэффициентов. Альтернатива влияет на p-value наклона, но не на интервалы.

Для каждой использованной строки сохраняются прогноз и остаток `наблюдаемое Y − прогноз`. При постоянном Y R² не определён. При точном совпадении всех точек с прямой остаточная ошибка равна нулю; приложение сохраняет модель, но не выдаёт p-value и интервалы коэффициентов, основанные на оценке случайной ошибки.

Для вывода о коэффициентах существенны линейность, независимость, постоянство дисперсии и распределение остатков. Состав показателей и тест наклона соответствуют обычной простой OLS-модели, описанной, например, в [SciPy `linregress`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.linregress.html). Множественная, взвешенная, смешанная и нелинейная регрессия пока отсутствуют.

### Общие ограничения вывода

Программа не выбирает метод автоматически, не проверяет дизайн исследования, не исправляет множественные сравнения и не заменяет оценку размера эффекта решением по одному p-value. Q–Q-график является визуальной диагностикой, а не автоматическим тестом нормальности. Предупреждение при менее чем 10 наблюдениях — напоминание о малом объёме, а не универсальный порог применимости методов.

Все расчёты используют `double`. Численное переполнение или нечисловой результат вызывают ошибку вместо записи вымышленного нуля. Отсутствующая оценка хранится как `null`; p-value, округлившийся до нуля в машинном представлении, в тексте обозначается как «меньше машинной точности».

## 5. Графики и экспорт рисунков

В сохранённом результате нажмите **«Графики»**. Доступны:

- гистограмма X: равные интервалы, правило `ceil(log2(n) + 1)` с ограничением 5–40 интервалов; для постоянного массива один интервал;
- ряд X в порядке использованных наблюдений;
- диаграмма рассеяния X/Y для парных данных, с линией модели для регрессии;
- ящик с усами: квартили type 7, усы до крайних наблюдений в пределах `1,5 × IQR`, отдельные точки за усами;
- средние с двусторонними t-интервалами **каждого среднего**: это не интервал разности и не замена парного теста;
- отдельные наблюдения по группам с небольшим горизонтальным сдвигом только для различимости точек;
- Q–Q для X: теоретические квантили стандартного нормального распределения с вероятностями `(i + 0,5) / n`, отсортированные X и линия через квартильные точки;
- для регрессии — остатки против прогнозов и отдельный Q–Q-график остатков.

Гистограмма, сводные показатели и модель используют все наблюдения. На диаграммах с множеством точек рисуется до **3 000** точек/пар на серию, выбранных равномерно по индексу; это сокращение только отображения. Для значений за усами показывается до **300** точек на группу. Ограничение объяснено под графиком. Сам массив и результаты расчёта сохраняются полностью. Ряд наблюдений при сокращении соединяет отображённые точки; для детального изучения всего временного ряда экспортируйте данные.

Можно изменить заголовок и подписи, сохранить **SVG 1120 × 720** или **PNG 2240 × 1440, 192 dpi**. Рисунки имеют белый фон независимо от темы интерфейса. Окончательное оформление рисунка можно изменить во внешнем векторном редакторе. Настройки подписей действуют в открытом окне графика; отдельные стили рисунков в БД пока не сохраняются. При чрезмерном числовом диапазоне рисунок требует изменения масштаба/единиц.

## 6. Что сохраняется в результате

`AnalysisRun` содержит название, проект, набор, **DatasetVersionId**, название метода, **ParametersJson**, **ResultJson**, русский текст **Summary**, комментарий и версию вычислительного модуля. В истории доступен переход к использованной версии таблицы. Комментарий сохраняется кнопкой, при выходе из результата и перед экспортом.

Экспорт TXT предназначен для чтения. Экспорт JSON содержит весь `AnalysisRun`; `ParametersJson` и `ResultJson` внутри него — строки JSON. Для программного чтения их нужно десериализовать второй раз. Полный результат имеет следующую структуру:

| Поле | Содержание |
| --- | --- |
| `Metrics` | Массив `{ Key, Label, Value }`; числовой `Value` либо `null`. |
| `UsedRows`, `UsedRowsY` | Номера строк для X/Y в той же последовательности, что массивы значений. Для полных пар списки совпадают. |
| `OmittedRows`, `OmittedRowsX`, `OmittedRowsY` | Объединённый и отдельные списки пропусков/исключений. |
| `OmissionReasons` | Словарь «номер строки → причина». |
| `X`, `Y` | Числовые массивы, фактически использованные в расчёте. |
| `Fitted`, `Residuals` | Прогнозы и остатки регрессии, согласованные с `UsedRows`. |
| `QqX`, `QqY` | Теоретические квантили N(0, 1) и отсортированный X. Q–Q остатков строится из `Residuals`. |
| `Inference`, `Warnings`, `Summary` | Описание метода, условия применения и читаемый отчёт. |

Основные ключи `Metrics`: `n`, `mean`, `median`, `sd`, `se`, `min`, `max`, `q1`, `q3`, `ci_low`, `ci_high`; для двух групп описательные показатели имеют префиксы `x_`/`y_`. Тесты добавляют `difference`, `standard_error`, `t`, `df`, `p`, `cohen_d` либо `cohen_dz`. Корреляция — `r`, точный Спирмен — `permutations`. Регрессия — `intercept`, `slope`, `r_squared`, `residual_se`, `slope_se`, `intercept_se` и границы интервалов `slope_ci_low/high`, `intercept_ci_low/high`. Все результаты содержат `excluded_count` и `omitted_count`.

Параметры `XColumn`, `YColumn`, `GroupColumn`, `IdColumn` в API и JSON имеют индексы **от нуля**; номера исключённых строк — **от единицы**. Перечисления сериализуются числами: `StatisticalMethod` — Descriptive=0, WelchTTest=1, PairedTTest=2, Pearson=3, Spearman=4, LinearRegression=5; `AlternativeHypothesis` — TwoSided=0, Less=1, Greater=2.

`DatasetVersion.SourceHash` — SHA-256 исходного импортированного файла. При ручных правках он сохраняет связь с источником и **не является хешем изменённых ячеек**. Подлинный источник расчёта — неизменяемая версия с её ID, строками и параметрами анализа.

## 7. Контрольные проверки и пример

В `tests/YoungScientistDiary.SelfTests/AnalysisTests.cs` проверяются CSV с кавычками и многострочными ячейками, десятичная запятая, XLSX и CSV после обратного экспорта, пропуски, сохранность пар, дубликаты ID, ошибочные числа, независимость от культуры и отсутствие изменения версии при анализе. Численные значения для описательной статистики, Уэлча, парного теста, Пирсона и OLS сравниваются с заранее полученными независимыми результатами SciPy. Точный Спирмен проверяется по известному полному числу перестановок. Тесты не требуют Python: эталонные значения включены в C#.

Для проверки вручную импортируйте `samples/regression.csv` с разделителем `;` и заголовком. Выберите линейную регрессию, X и Y. Ожидаются наклон примерно **1,965714286**, свободный член **−0,08**, стандартная ошибка наклона **0,087784523**, двусторонний p-value около **0,0000235499**. В `samples/experiment.csv` находятся учебные данные с группами, ID, измерениями до/после и пропуском. Это искусственные примеры для освоения программы, не результаты исследования.

Возможности ANOVA, непараметрических сравнений групп, многофакторных моделей, расчёта мощности, доверительных интервалов bootstrap, множественной импутации и автоматической обработки технических повторов относятся к последующим расширениям. Базовая архитектура отделяет импорт, неизменяемые данные и вычислительный модуль от WPF-интерфейса.
